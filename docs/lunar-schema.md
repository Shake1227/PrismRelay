# Verified Lunar configuration schema

Prism Relay 1.0.0 inspected the key names and JSON types of locally installed Lunar game settings on 2026-09-30. The inspection was read-only. No account or authentication files were opened. No real values were copied into this repository, fixtures, logs, or share codes.

The verified layout is `.lunarclient/settings/game/<profile>/`, containing `mods.json`, `general.json`, `controls.json`, and `performance.json`. Those profiles are Lunar GUI presets. The Minecraft game destination is the OS default game directory, or the one game directory explicitly chosen in Settings. It is not selected through launch configurations.

In 1.0.2, scanning exposes one Minecraft game destination. Windows uses `%APPDATA%/.minecraft`; macOS uses `~/Library/Application Support/minecraft`. Alternate version folders and Lunar isolated profiles are not scanned as game destinations. A custom game directory can be specified in Settings. This avoids applying a code to an unused version folder.

When the chosen game directory contains `optionsLC.txt`, its flat JSON string settings and the adjacent `options.txt` belong to that same destination. Import updates selected keys present in each file within a single backup transaction, preferring the LC value for export. Regular-options-only keys are not invented in LC. A damaged or unsupported existing LC file blocks that destination's game settings.

LC stores FOV as a degree string from 30 to 110; Minecraft's regular options file stores the normalized ratio from -1 to 1. Their relationship is `degree = 70 + 40 * ratio`. This conversion and the string-reading behavior were checked against the installed Minecraft 1.21.11 and Lunar game code. Shared codes continue to use the existing Minecraft options string schema. LC values with other JSON types or values outside approved grammars remain read-only. JSON token updates preserve unknown fields, precision, whitespace, and byte order marks.

`mods.json` has an object root. Its module objects use names such as `FPS`, `CPS`, `COORDINATES`, `KEYSTROKES`, and `ARMORSTATUS`. HUD children can be nested inside a module. Observed leaves include boolean `enabled`, numeric `x` and `y`, string `position`, and nested `options`. Options can contain booleans, numeric strings, keybind strings, and color objects with numeric `value` and boolean `chroma` fields. Root `version`, module `panelIndex`, `seen`, and `lastModified` fields are metadata and are excluded from sharing.

`general.json` and `controls.json` have object roots. Confirmed general settings include appearance booleans and a `backgroundColor` object. Confirmed controls include keybind strings and separate modifier booleans. Some profiles contain only a schema version or an empty object. `performance.json` was observed with an object root and string enum fields whose semantics were not verified; it remains read-only in this release.

[src-tauri/src/lunar_schema.json](../src-tauri/src/lunar_schema.json) is the closed allowlist of observed, approved paths and their scalar types. It contains key names and type descriptions only. Export enumerates keys actually present in each file. A known module whose root `enabled` boolean is explicitly shared can be updated even when that leaf is absent in the destination, provided the module object exists. The module-specific factory default is not inferred for export. Newly introduced keys remain untouched until their schema and privacy properties are reviewed.

Strings use bounded grammars. Position strings are accepted only when they match a closed direction vocabulary after case and separator normalization. Of the inspected position fields, 102 matched this grammar and 19 did not; the latter remain read-only. Numeric option strings must parse as bounded finite numbers. Keybind strings must identify a recognized keyboard or mouse key. Free text, unknown enums, custom crosshair payloads, macro actions, account fields, server addresses, waypoint coordinates and payloads, Quickplay data, and unknown arrays are excluded.

HUD coordinates are exposed exactly as stored. The inspected schema does not establish portable source resolution metadata or the complete meaning of every anchor string. Prism Relay therefore performs no guessed coordinate normalization or scaling. The import preview tells users that the resulting layout can differ on another display.

The Lunar parser rejects duplicate JSON keys, damaged JSON, excessive arrays or objects, and oversized files. Import merges verified scalar paths present in the destination, with the narrowly scoped root-module `enabled` insertion described above. JSON scalar types must match, except for four inspected numeric-string/number pointers that are converted to the destination format after validation. It patches only the selected scalar tokens in the original JSON text. Unknown values, numeric precision, field ordering, escaping, and whitespace are preserved byte-for-byte. Files and traversed directories that are symlinks are denied. These guarantees do not make this an official Lunar integration: future Lunar releases can change the schema, and unsupported fields intentionally remain read-only.

The active Lunar GUI preset is read locally from `profile_manager.json`. Its `name` must match a discovered preset directory exactly, and exactly one entry must have `active=true`. Server, display-name, icon, and other manager fields are excluded from settings and share codes. The GUI uses this preset as the initial choice while retaining a valid explicit user choice.
