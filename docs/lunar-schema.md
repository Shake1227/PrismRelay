# Verified Lunar configuration schema

Prism Relay 1.0.0 inspected the key names and JSON types of locally installed Lunar game settings on 2026-09-30. The inspection was read-only. No account or authentication files were opened. No real values were copied into this repository, fixtures, logs, or share codes.

The verified layout is `.lunarclient/settings/game/<profile>/`, containing `mods.json`, `general.json`, `controls.json`, and `performance.json`. Minecraft game options are also stored under `.lunarclient/profiles/<version>/`. The installed options files used modern `key.keyboard.*` binding values and contained Lunar `key_Freelook` and OptiFine `key_of.key.zoom` bindings. The parser also accepts bounded legacy numeric key codes. Profiles and version folders are discovered locally. A manually selected game settings folder or individual profile is supported.

For 1.0.1, a read-only inspection on 2026-10-01 confirmed that Lunar 1.21.11 stored game options in the `1.21` profile directory. Alongside `options.txt`, `optionsLC.txt` contained a flat JSON object whose option values were strings. Prism Relay exposes approved keys from both files in one game profile, preferring the LC value where both files contain the same key. Import updates only selected keys already present in each file, within a single backup transaction. Keys present only in the regular options file remain available without being added to LC. An existing damaged or unsupported LC file blocks that profile's game settings.

LC stores FOV as a degree string from 30 to 110; Minecraft's regular options file stores the normalized ratio from -1 to 1. Their relationship is `degree = 70 + 40 * ratio`. This conversion and the string-reading behavior were checked against the installed Minecraft 1.21.11 and Lunar game code. Shared codes continue to use the existing Minecraft options string schema. LC values with other JSON types or values outside approved grammars remain read-only. JSON token updates preserve unknown fields, precision, whitespace, and byte order marks.

In a Vanilla Minecraft folder, LC appears as a separate Lunar profile. Selecting that profile updates its LC file while the Vanilla options file remains part of the separate Vanilla profile. Each physical file is registered once, including when custom scan roots overlap.

`mods.json` has an object root. Its module objects use names such as `FPS`, `CPS`, `COORDINATES`, `KEYSTROKES`, and `ARMORSTATUS`. HUD children can be nested inside a module. Observed leaves include boolean `enabled`, numeric `x` and `y`, string `position`, and nested `options`. Options can contain booleans, numeric strings, keybind strings, and color objects with numeric `value` and boolean `chroma` fields. Root `version`, module `panelIndex`, `seen`, and `lastModified` fields are metadata and are excluded from sharing.

`general.json` and `controls.json` have object roots. Confirmed general settings include appearance booleans and a `backgroundColor` object. Confirmed controls include keybind strings and separate modifier booleans. Some profiles contain only a schema version or an empty object. `performance.json` was observed with an object root and string enum fields whose semantics were not verified; it remains read-only in this release.

[src-tauri/src/lunar_schema.json](../src-tauri/src/lunar_schema.json) is the closed allowlist of 465 observed, approved paths and their scalar types. It contains key names and type descriptions only. Parsing enumerates the actual keys present in each file; absent keys are not invented. Newly introduced keys remain untouched until their schema and privacy properties are reviewed.

Strings use bounded grammars. Position strings are accepted only when they match a closed direction vocabulary after case and separator normalization. Of the inspected position fields, 102 matched this grammar and 19 did not; the latter remain read-only. Numeric option strings must parse as bounded finite numbers. Keybind strings must identify a recognized keyboard or mouse key. Free text, unknown enums, custom crosshair payloads, macro actions, account fields, server addresses, waypoint fields, Quickplay data, and unknown arrays are excluded.

HUD coordinates are exposed exactly as stored. The inspected schema does not establish portable source resolution metadata or the complete meaning of every anchor string. Prism Relay therefore performs no guessed coordinate normalization or scaling. The import preview tells users that the resulting layout can differ on another display.

The Lunar parser rejects duplicate JSON keys, damaged JSON, excessive arrays or objects, and oversized files. Import merges only verified scalar paths already present in the destination, and requires matching JSON scalar types. It patches only the selected scalar tokens in the original JSON text. Unknown values, numeric precision, field ordering, escaping, and whitespace are preserved byte-for-byte. Files and traversed directories that are symlinks are denied. These guarantees do not make this an official Lunar integration: future Lunar releases can change the schema, and unsupported fields intentionally remain read-only.
